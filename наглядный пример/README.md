# Наглядный пример — демонстрация уязвимостей TaskBarHero

Утилита для показа найденных уязвимостей вживую. Слева выбираются изменения,
справа видно, что на них ответил сервер.

---

## Быстрый старт на встрече

1. Запустить игру TaskBarHero, дождаться загрузки сейва.
2. `ЗАПУСК.bat`
3. Если ключа нет — утилита покажет отпечаток машины. Выпустить ключ генератором,
   вставить в окно.

Требуется Python 3 и `pycryptodome` (`pip install pycryptodome`).
Интернет обязателен — без него нельзя проверить срок ключа.

---

## Как устроено окно

### Слева — два блока, разделённых по характеру последствий

**1 · СОХРАНЯЕТСЯ НА СЕРВЕРЕ (красный)**

Изменение уходит в сейв и переживает полный перезапуск. Сервер принимает его как
легитимное, предупреждения о вмешательстве нет.

- характеристики героев (F-01) — здоровье, атака, любой узел дерева
- руны (F-02) — прокачка и разблокировка закрытых
- превышение бюджета очков (F-03) — показывается автоматически, когда сумма
  уровней уходит выше `AllocatedHeroAbilityPoint`

**2 · ТОЛЬКО ПОКА ИГРА ЗАПУЩЕНА (оранжевый)**

Само изменение при перезапуске сбросится. Но всё, что игрок успел получить за его
счёт — золото, лут, стадии — начислено штатным кодом игры и остаётся навсегда.

- таблица цен рун (F-04) — 272 строки в обычной read/write памяти

Сюда же относятся ХП мобов и дроп золота по уровням. В нашем тесте они **не были
локализованы**, поэтому в отчёте помечены как непроверенные — на встрече это стоит
проговорить честно.

### Справа — ответ сервера

- **Проверить ответ сервера** — ждёт собственный автосейв игры (до ~3 мин), затем
  расшифровывает сейв и сверяет значения. Это единственный корректный способ
  подтвердить, что изменение принято: чтение файла сразу после записи показывает
  собственную запись, а не решение сервера.
- **Показать защищённое (контроль)** — атакует золото тем же способом и показывает,
  что защита срабатывает. Это главный аргумент встречи: механизм у разработчика
  **есть и работает**, он просто не применён к блоку 1.

---

## Какие значения ставить на демонстрации

**Умеренные.** 50–200 для характеристики, 5–10 для руны.

Значения вроде 99999 работают на уровне сейва (записываются и переживают
перезапуск), но игра упирается в предел при расчёте статов, и герой визуально
не становится сильнее — со стороны выглядит так, будто ничего не сработало.
Плюс сумма ветки уходит в сотни тысяч при бюджете в 22 очка, и разработчик
резонно скажет «это же явный мусор, мы такое отфильтруем».

Умеренное значение убедительнее: оно выглядит как настоящий чит, проходит
все проверки и даёт видимый эффект.

---

## Порядок показа (предлагаемый сценарий)

1. **Контроль первым.** Нажать «Показать защищённое». Золото +123 456 → откат.
   Тезис: защита есть и она рабочая.
2. **Красный блок.** Поднять здоровье героя, «Проверить ответ сервера».
   Значение в сейве. Тезис: та же атака, тот же способ — но здесь принято.
3. **Разблокировка руны.** Взять руну с уровнем 0, поставить 1.
   Тезис: отдельного флага открытия нет, `0 → 1` и есть разблокировка,
   между одним узлом и всем деревом только счётчик цикла.
4. **Оранжевый блок.** Показать таблицу цен. Тезис: балансные конфиги лежат
   открыто; сброс при перезапуске не спасает, потому что добытое остаётся.
5. **Откатить всё** — вернуть аккаунт в исходное состояние.

## Ключи доступа

Утилита не запускается без действующего ключа. Ключ привязан к отпечатку машины
и к **сетевому** времени (локальные часы не используются — их можно перевести назад).

### Выпуск

`keygen\ЗАПУСК-ГЕНЕРАТОР.bat`

- вставить отпечаток машины (16 символов, утилита показывает его сама)
- задать длительность и количество
- несколько ключей выдаются **последовательными окнами**: второй активируется,
  когда истёк первый. Три ключа по 30 минут = 1.5 часа непрерывной работы.

Для одного ключа — сохранить файл как `license.key` рядом с `demo.py`.

### Что схема даёт и чего не даёт

**Даёт.** Ключ невозможно подделать без приватного ключа генератора: подпись Ed25519,
в утилите только публичная часть. Утёкшая копия не может выписать себе ключ —
подписывать нечем. Ключ бесполезен на другой машине и после истечения срока.

**Не даёт.** Защиту от того, кто пропатчит саму проверку. Любое клиентское решение
«продолжать или нет» — это условный переход в бинарнике. Обещать «нельзя вырезать
таблеткой» было бы нечестно: это ровно тот класс проблем, который мы описываем
в отчёте по игре.

**Вывод.** Задача лицензии — остановить того, кто *случайно* получил утёкшую копию.
Для этого достаточно. Тот, кто способен снять проверку, способен и переписать
утилиту с нуля по отчёту: возможности здесь не секрет, они все описаны.

### Приватный ключ

`keygen\signing_key.pem` — **не передавать никому и не носить на встречу**.
Без него ключи выписать невозможно, в этом весь смысл схемы.

## Файлы

| Файл | Что делает |
|---|---|
| `demo.py` | интерфейс демонстрации |
| `core.py` | чтение сейва (ES3) и работа с памятью процесса |
| `licensing.py` | проверка ключа, отпечаток машины, сетевое время |
| `license.key` | текущий ключ |
| `keygen\keygen.py` | выпуск ключей (здесь приватный ключ) |
| `ОТПЕЧАТОК-МАШИНЫ.bat` | напечатать отпечаток, не запуская утилиту |

Подробный отчёт с находками — в соседней папке `..\test-results\`.

## Если что-то не работает

**«игра: не запущена»** — запустить TaskBarHero, нажать «Обновить состояние».

**«нет доступа к интернету»** — ключ привязан к сетевому времени, офлайн работать
не будет. На встрече проверить, что сеть есть.

**«ключ выписан для другой машины»** — отпечаток считается из MachineGuid, UUID
материнской платы, ID процессора и серийника диска C:. Меняется при переустановке
системы или замене диска — нужен новый ключ.

**Объект не найден при применении** — игра перезапустилась, адреса изменились.
Нажать «Обновить состояние».
