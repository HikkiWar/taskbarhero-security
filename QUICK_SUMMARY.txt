ТЕКУЩИЙ СТАТУС ОТЧЁТА: Найдено 8 уязвимостей (F-01 до F-08), проверено и задокументировано

ВЫЯВЛЕННЫЕ ПРОБЕЛЫ: 4 вещи, которые требуют срочного тестирования


┌─────────────────────────────────────────────────────────────────────────────┐
│ 1️⃣  ПОДМЕНА СЕТЕВОГО ТРАФИКА (Network Hijacking) — CRITICAL ⚠️            │
├─────────────────────────────────────────────────────────────────────────────┤
│ ПРОБЛЕМА:                                                                    │
│   • F-06 доказал: пароль шифрования сейва СКОМПРОМЕТИРОВАН                │
│   • Алгоритм известен: PBKDF2-HMAC-SHA1 + AES-128-CBC                      │
│   • Можно ПОЛНОСТЬЮ перешифровать сейв с подменёнными данными             │
│                                                                              │
│ НЕИЗВЕСТНО:                                                                 │
│   ? Есть ли серверная проверка ПОДПИСИ всего архива?                       │
│   ? Работает ли проверка целостности на уровне полей или только файла?    │
│   ? Может ли сервер принять переш cifрованный сейв с чужими значениями?   │
│                                                                              │
│ РИСК:                                                                        │
│   Если сервер недостаточно проверяет переш cifрованные данные —           │
│   → все остальные защиты (F-01...F-08) + новые F-09...F-12 = бесполезны   │
│                                                                              │
│ ТЕСТИРОВАНИЕ:                                                               │
│   1. Расшифровать сейв (алгоритм из F-06)                                 │
│   2. Изменить одно значение (напр. maxCompletedStage: 1207 → 1307)        │
│   3. Переш cifровать тем же ключом                                          │
│   4. Закинуть в папку сохранений                                           │
│   5. Запустить игру → дождаться автосейва → перезагрузить                │
│   6. Проверить в расшифрованном сейве: сохранилось ли изменённое значение │
│                                                                              │
│ ВРЕМЯ: ~3-4 часа (включая извлечение пароля)                              │
│ ПРИорИТЕТ: HIGHEST — проверить СРАЗУ                                      │
└─────────────────────────────────────────────────────────────────────────────┘


┌─────────────────────────────────────────────────────────────────────────────┐
│ 2️⃣  СИНТЕЗ КУБА (Cube Synthesis) — HIGH ⚠️                                │
├─────────────────────────────────────────────────────────────────────────────┤
│ ПРОБЛЕМА:                                                                    │
│   • Система синтеза кубов ВООБЩЕ НЕ ТЕСТИРОВАЛАСЬ                        │
│   • Классы найдены: CubeLevelSaveData, CubeRecipeSaveData, CubeSynthesisLog│
│   • Возможна АНАЛОГИЯ с F-01 (отрицательная цена начисляет ресурсы)      │
│                                                                              │
│ ГИПОТЕЗА:                                                                   │
│   • Рецепты хранят стоимость (gold/materials) как обычное число           │
│   • Нет проверки на отрицательность стоимости                              │
│   • При синтезе с cost < 0 → ресурсы ДОБАВЛЯЮТСЯ вместо траты            │
│                                                                              │
│ ТЕСТИРОВАНИЕ:                                                               │
│   1. Найти CubeRecipeSaveData в памяти (Cheat Engine)                     │
│   2. Локализовать поле стоимости рецепта                                  │
│   3. Изменить cost: 1000 → -1000                                          │
│   4. Попытаться синтезировать куб                                          │
│   5. Дождаться автосейва, перезагрузить, проверить расшифр. сейв         │
│   6. Если ресурсы добавились → УЯЗВИМО (severity HIGH)                    │
│                                                                              │
│ ВРЕМЯ: ~2-3 часа                                                            │
│ ПРИОРИТЕТ: HIGH (второй после Network Hijacking)                           │
└─────────────────────────────────────────────────────────────────────────────┘


┌─────────────────────────────────────────────────────────────────────────────┐
│ 3️⃣  ПОДМЕНА РЕДКИХ СУНДУКОВ (Rare Box Rolls) — HIGH ⚠️                    │
├─────────────────────────────────────────────────────────────────────────────┤
│ ПРОБЛЕМА:                                                                    │
│   • F-07 доказал: содержимое сундуков ИЗВЕСТНО ЗАРАНЕЕ (в памяти)         │
│   • Структура BoxData выявлена и раскладка известна                        │
│   • НО: не проверена возможность ИЗМЕНИТЬ РАРНОСТЬ сундука                 │
│                                                                              │
│ ГИПОТЕЗА:                                                                   │
│   • BoxData содержит тип сундука (910651 = обычный, 920651 = редкий)     │
│   • Можно изменить тип обычного сундука на редкий В ПАМЯТИ                │
│   • Сервер возьмёт изменённый тип и выдаст редкую награду?               │
│                                                                              │
│ ТЕСТИРОВАНИЕ:                                                               │
│   1. Из box_queue_prediction.json найти сундук (920651 = редкий)          │
│   2. Найти его адрес в памяти (ASLR может плыть)                          │
│   3. Скопировать данные редкого в соседний обычный сундук                 │
│   4. ИЛИ просто изменить поле типа: 910651 → 920651                      │
│   5. Открыть сундук в игре                                                 │
│   6. Проверить: выпал ли редкий предмет?                                  │
│   7. Дождаться автосейва и перезагрузки                                    │
│   8. Если редкая награда осталась → УЯЗВИМО (severity HIGH)               │
│                                                                              │
│ ВРЕМЯ: ~2-3 часа                                                            │
│ ПРИОРИТЕТ: HIGH (третий)                                                   │
└─────────────────────────────────────────────────────────────────────────────┘


┌─────────────────────────────────────────────────────────────────────────────┐
│ 4️⃣  ТАБЛИЦА ВЕРОЯТНОСТЕЙ ДРОПА (Drop Probability) — MEDIUM ⚠️             │
├─────────────────────────────────────────────────────────────────────────────┤
│ ПРОБЛЕМА:                                                                    │
│   • Вероятность выпадения редких предметов НЕ ПРОВЕРЕНА                    │
│   • Если таблица весов ЛОКАЛЬНАЯ → можно изменить шансы                    │
│   • Пример: редкие 5% → 100% обычные 0%                                    │
│                                                                              │
│ ГИПОТЕЗА:                                                                   │
│   • Игра хранит массив [ID, weight] пар локально                          │
│   • Клиент использует эти веса для Random выбора при открытии сундука     │
│   • Сервер просто отправляет разыгранную награду и верит клиенту         │
│                                                                              │
│ ТЕСТИРОВАНИЕ:                                                               │
│   1. Найти таблицу весов (поиск по float 0.05, 0.25, 0.7 в памяти)       │
│   2. Локализовать поле для редких предметов                                │
│   3. Изменить вес редких: 0.05 → 1.0 (100%)                               │
│   4. Изменить вес обычных: 0.7 → 0.0                                       │
│   5. Открыть 10-20 сундуков подряд                                         │
│   6. Подсчитать: сколько выпало редких?                                    │
│   7. Если >> 50% редких → УЯЗВИМО (severity MEDIUM-HIGH)                  │
│                                                                              │
│ ВРЕМЯ: ~1-2 часа                                                            │
│ ПРИОРИТЕТ: MEDIUM (четвёртый, но можно паралелить с другими)              │
└─────────────────────────────────────────────────────────────────────────────┘
